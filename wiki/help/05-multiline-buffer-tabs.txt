==============================================================================
MULTILINE BUFFER TABS                                    *bufferline-multiline*

Multiline is opt-in. The native single-row renderer remains the default, with
its existing defaults and Neovim 0.8+ minimum unchanged. Multiline requires
Neovim 0.12+ and `options.mode = "buffers"`.

Multiline is available on the main branch of MOSconfig/bufferline.nvim, not in
upstream tags. Install this fork to use it:
https://github.com/MOSconfig/bufferline.nvim

Add multiline to your complete configuration. Each setup() call takes a complete
configuration, not an incremental options update. Retain the original table so
native-only settings can be restored without losing custom options/highlights.
>lua
    local bufferline = require("bufferline")
    local original_config = {
        options = {
            -- Keep all your existing options here.
        },
        -- Keep other setup fields, such as highlights, here too.
    }
    local multiline_config = vim.deepcopy(original_config)
    multiline_config.options = multiline_config.options or {}
    multiline_config.options.mode = "buffers"
    multiline_config.options.multiline = { enabled = true, max_rows = 3 }
    bufferline.setup(multiline_config)
<
`options.multiline.enabled` defaults to false. `max_rows` defaults to 3 and must
be a positive integer. It caps buffer rows, excluding Neovim's normal split
separator/statusline space. The header is a reserved split above the editor,
not a taller native tabline. Sidebars remain outside its area. Wrapping uses the
header window's actual width; native sidebar offsets are not repeated here.
The scratch buffer has filetype=bufferline. File explorers should exclude this
filetype from replacement targets (Neo-tree: open_files_do_not_replace_types).

Set tab_size with enforce_regular_tabs = true and truncate_names = true to
adjust entry width and trim long titles. Enable show_buffer_close_icons for
clickable per-buffer close buttons, whose behavior follows close_command.
Modified buffers show their modification indicator instead of the close icon.

Compatibility ~

When omitted, `show_tab_indicators` and the global `show_close_icon` become false
in multiline mode only. Explicit true values are rejected: remove these
native-only overrides or set them to false in the multiline copy. Per-buffer
close icons (`show_buffer_close_icons`) remain supported. Tabpage mode
(`mode = "tabs"`), `custom_areas`, and hover reveal are unsupported. Remove custom
areas and disable `hover.enabled` before enabling multiline.

Unicode labels, icons, diagnostics, groups, pinned buffers, and buffer/close/group
click actions work across rows. Nerd Font chevrons with hidden-buffer counts and the
mouse wheel scroll rows beyond the cap. Changing the current buffer reveals its
row. Existing user mouse mappings run first and may consume click or wheel
events before bufferline receives them; bufferline does not override that
precedence. See |bufferline-mouse-actions| for configurable click commands.

Keyboard navigation ~

Use normal window navigation (|CTRL-W_k| from the editor below the header) to
enter the header. Only the header scratch buffer has these Normal-mode maps:

    h / l       Previous / next buffer candidate (no wrap at the ends).
    j / k       Nearest candidate on the next / previous packed buffer row.
                Skip group-only rows and scroll hidden rows into view.
    <CR>        Run the candidate's configured left-click action in the captured
                ordinary editor window, falling back to another valid editor.
    <Esc>       Return to that editor without selecting a buffer.
    x           Run close_command on the candidate without activating it.
                Works with close icons hidden. Retains header focus and selects
                the next surviving neighbor (previous at the end). A refused
                close retains the candidate. Configure a nonforced close_command
                to protect unsaved buffers.

The whole active entry uses BufferLineBufferSelected; the whole keyboard
candidate uses IncSearch, including icons, padding, separators and suffixes.
Navigation does not change the editor buffer until <CR>. Groups, close icons,
and overflow controls are not keyboard candidates. Candidate buffer IDs survive
resize/repacking; removed or hidden candidates reconcile to the active buffer
(or first available candidate). Wheel scrolling works with either editor or
header focus and does not select a buffer. No global mappings are installed.

There is no `q` mapping in the header. The maps above are the complete set:
h, j, k, l, x, <CR> and <Esc>. In the header `q` keeps its usual Normal-mode
meaning and starts a macro recording, so use <Esc> to leave the header.
The header stays in its editor region when a full-height sidebar opens later.

Restoring single-row mode ~

Use a copy of the original complete configuration, not just a table containing
the multiline flag. This also restores any native-only settings you removed
from the multiline copy.
>lua
    local single_row = vim.deepcopy(original_config)
    single_row.options = single_row.options or {}
    single_row.options.multiline = single_row.options.multiline or {}
    single_row.options.multiline.enabled = false
    bufferline.setup(single_row)
<
Lifecycle and limitations ~

`options.multiline.enabled` is the only renderer selector. While it is enabled
the native single row never reappears, not even while no header is on screen.
Only setup() with `enabled = false` switches back, e.g. the single_row config
above. Configured selection and momentary readiness are separate concerns:

- Temporarily unavailable: the header for a tabpage is removed and the tabline
  is left empty when it cannot be drawn (too little height, an unusable frame,
  a failed allocation), when the header window is closed manually or by |:only|,
  or when a foreign buffer takes over the header window. Only that tabpage is
  affected; other tabpages keep their headers.
- Recovery is event-driven. The next buffer, window, resize or refresh event
  redraws the header. There is no polling and no retry loop, and setup() does
  not need to be called again. A genuine rendering error is reported once per
  failing episode; capacity limits are not reported at all.
- Commands while unavailable: |BufferLinePick| and the other pick commands do
  not block for a keypress when no header is on screen. They report
  "cannot pick while the multiline header is unavailable" and return, instead
  of waiting for input against letters you cannot see. Cycling commands such as
  |BufferLineCycleNext| keep working: they recompute the current state before
  navigating, so ordering stays correct even when nothing is rendered.
- Quitting: closing one editor split with |:q| keeps the header. When the last
  editor of a tabpage quits, its header is removed first so it cannot block quit.
  Sidebars and utility windows do not count as editors; their plugins control
  automatic closure (for example Neo-tree's close_if_last_window option).
  A refused quit, such as |E37| for an unsaved buffer, restores the
  header once the layout settles.
- Disabling, session loading, or auto-hide while the header is focused returns
  to the remembered eligible editor (or another available editor). In the
  header, <Esc> returns to the editor and never quits it. |:q| typed in the
  header does close the header window and return you to the editor, and the
  header is recreated once the layout settles. Unsaved editor buffers are
  never deleted by teardown.
- Loading a session pauses multiline: no header and no native row until
  |SessionLoadPost|, after which the header returns on its own.
- |:close|, |:hide|, or an API close of the last editing window can report |E855|.
  In the last tabpage the editing window remains; with other tabs open, Neovim
  may finish closing that tab despite the error. Use
  |:q| for ordinary quitting. Native unsaved-change checks remain; with 'hidden'
  enabled, modified buffers can remain hidden as usual.
- Disable multiline before |:mksession|, using the complete single-row setup
  above. Default 'sessionoptions' includes `blank`, so a session may save the
  anonymous `nofile` header window. Transparent session save/restore is not
  supported.
